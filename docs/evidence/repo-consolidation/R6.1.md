# R6.1 One-command dev stack

- `infra/docker-compose.yml` (existing: Postgres 17.6 pinned by digest, loopback-only port, named volume, healthcheck) now takes optional `JH_COMPOSE_PROJECT`, `JH_PG_CONTAINER`, `JH_PG_VOLUME`; `scripts/dev-stack.ps1` reads the container name from `JH_PG_CONTAINER`. Defaults are unchanged. Reason: Docker Desktop restarts the owner's existing `jobhunter-s1-pg` and `jobhunter-m3-pg` containers, so the integration checkout runs its own container (`jobhunter-integration-pg`, volume `jobhunter_integration_pgdata`, port 55450) with random local secrets in an ignored `infra/.env`. The owner's containers and volumes were not touched.
- `npm run dev:stack` from a cold start: PostgreSQL healthy -> 12 migrations applied on an empty database (0001-0005, 0006-0011 ML, 0012_m4_decision_intelligence; 39 public tables incl. job_match_reports.decision) -> AI service (venv created once) healthy on 8765 -> API healthy on 8787 -> web healthy on 4321. `npm run dev:stack:status` shows all four healthy. `npm run dev:stack:stop` stops API, AI and UI (PostgreSQL keeps running unless `-StopDb`).
- `infra/.env.example` committed (placeholder values only, optional overrides documented), `infra/.env` ignored (`git check-ignore -v infra/.env`). Commands documented in infra/README.md.
