# Resume extraction service (S1)

Internal FastAPI service. It **proposes** source-backed facts from a PDF or DOCX; it never approves, decides eligibility, or touches
a database. The TypeScript API validates every response and every span before anything is stored.

## Contract (`schemaRevision` 1)

`POST /internal/v1/ai/extract-resume?fileType=pdf|docx`, body = raw file bytes, `Authorization: Bearer <JH_AI_SERVICE_TOKEN>`.

Success (`200`): `{ schemaRevision, parserRevision, fileType, text, textSha256, warnings[], facts[], stats }`.
Each fact: `kind`, `value`, `attributes`, `span {start, end, quote}`, `proposedBy` (`rules` | `qwen`), `notes`.
Offsets are **UTF-16 code units** into `text` (what JavaScript `String.slice` uses); Python converts, so non-BMP characters are safe.

Typed errors (`{ "error": { "code", "message" } }`): `UNAUTHORIZED` 401, `UNSUPPORTED_FILE_TYPE` 400, `FILE_TOO_LARGE` 413 (6 MB),
and `422` for `UNREADABLE_FILE`, `ENCRYPTED_PDF`, `TOO_MANY_PAGES` (limit 20), `NO_TEXT_LAYER` (scanned image; **no OCR is
performed**), `UNSAFE_DOCX`, `NO_DOCX_BODY`.

`GET /internal/v1/ai/info` reports `parserRevision` and whether the Qwen fallback is on. Interactive API docs are disabled.

## What it will and will not propose

* Proposes: `skill`, `employment` (only with a parseable month-level start date), `education`, `certification`, `project`, and
  the contact kinds `legal_name`, `email`, `phone` (marked sensitive downstream).
* **Never** proposes `citizenship`, `clearance`, `work_authorization` or `sponsorship_need`. If the resume mentions such a term the
  service returns a `SENSITIVE_TERM_NOT_IMPORTED` warning with the span and nothing else. The TypeScript side also refuses those
  kinds if the service ever emitted them.
* Never invents: year-only or unparseable dates are skipped with `EMPLOYMENT_DATE_PRECISION`; an employer/title order that cannot be
  determined is returned unsplit with a note; `employmentType` is set only to `internship` from an explicit keyword.
* Resume text is inert data. Instruction-like text is reported as `INSTRUCTION_LIKE_TEXT` and has no effect.

## Deterministic first, Qwen only when required

The rules parser (`app/parse_resume.py`) always runs. The local Qwen model (via Ollama on loopback) is consulted **only** when
`JH_AI_QWEN_FALLBACK=1` **and** the rules found no skill, employment or education fact in a document that has text. Qwen may only
return `{kind, quote}` pairs for `skill | education | certification | project`; code verifies each quote appears verbatim in the text,
computes the span, and drops everything else. Model output that is not valid JSON, or an unreachable model, is a warning
(`QWEN_FALLBACK_UNAVAILABLE`), never a failed extraction. The fallback is off by default and no model runs in the test suite.


`tests/fixtures/resume_cases.json` holds 14 hand-authored synthetic resumes (PDF and DOCX) with their expected facts, written from
the resume text and not generated by the parser. `tests/builders.py` turns them into real PDF/DOCX bytes. The TypeScript full-stack
test reads the same file.

Use a dedicated virtual environment: the machine-wide Python has unrelated packages.

## Parser revision `resume-rules@2`

* **Line breaks** (`app/linebreaks.py`): rules parse a repaired *view* of the text. `corre-` + newline + `lation` becomes `correlation` in the value, while
  the span and quote stay on the ORIGINAL characters (`event corre-
lation`), so the fact is verifiable against the document. Legitimate hyphens
  (`false-positive`, `self-service`) are kept; a break that cannot be classified is left untouched and reported as `LINE_HYPHEN_AMBIGUOUS`.
* **PDF word spacing**: `pdfplumber` is called with `x_tolerance=2` (default 3 fused words in tightly kerned PDFs). Text with long space-less runs still
  produces `TEXT_LAYER_MERGED_WORDS`.
* **Employment**: a title that merely contains "Intern" no longer assigns a category; only an `Internship` section heading does (and says so in `notes`).
  `Title Employer` with no separator is split only when the title keywords end clearly; otherwise it stays unsplit with a note.
* Mixed-case section headings (`Security Engineering Projects`), inline `•`-separated certification lists, `B.Tech.` degrees, LaTeX `[1pt]` artefacts and
  project technology lines are handled. Achievements are not facts; see `docs/RESUME-DIAGNOSTICS.md`.

`preview.py <file> <pdf|docx>` runs the current parser over a stored upload and prints the proposals (read-only; used by `resumes:diagnose --rerun-parser`).

## Shadow evaluation (`eval/`)

`eval/run_eval.py` compares the rules baseline with a local Qwen structured-extraction challenger on `eval/heldout_cases.json`
(11 regression + 7 stress synthetic résumés with hand-written labels). The challenger is **never** imported by the service
(`tests/test_shadow_rollback.py` enforces it); rollback is simply leaving `JH_AI_QWEN_FALLBACK` unset. Run it with `npm run ai:eval`.
Both the production fallback and the challenger refuse any proposal containing a citizenship/clearance/work-authorization/sponsorship term.
