# Decision: keep raw listings before relevance filtering

Problem: `src/discovery/orchestrator.ts` evaluated relevance and wrote only retained jobs. Rejected observations had no record, so later audits could not tell a filtered listing from a listing that was never seen.

Choice: append every evaluated listing to `listing-provenance.jsonl` before the candidate store is filtered. `discoveredJobs.jsonl` and resolution still receive only retained jobs. `postedAt` stays null until a source field supplies posting evidence. Employer coverage reads stored registry ATS ids and does not guess board tokens.

Limit: listings dropped before this change are gone. A careers URL in the watchlist is not a verified ATS identity. Owner sponsorship notes do not decide a posting.

Rollback: stop passing `provenancePath`. The candidate store behavior is unchanged.
